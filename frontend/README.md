# AutoLog · frontend

팀 저장소 `Mybread2/pleos-care-log` 루트에 **이 `frontend` 폴더 전체를 추가**하기 위한 웹 Mock 패키지입니다.

```text
pleos-care-log/
├── app/                 기존 Android 앱
├── mock-fixtures/       팀 Mock 원본
└── frontend/            이 폴더
```

팀 저장소 루트에서 `cd frontend` 후 아래 명령을 실행합니다. 자체 `.gitignore`와 `.gitattributes`가 포함돼 있고, 별도 `.git` 폴더는 없습니다. 기존 Android 파일이나 루트 Gradle 설정을 덮어쓰지 않습니다.

이 패키지는 브라우저에서 독립 실행하는 Mock 시연입니다. Android 앱에 웹 UI를 적용하거나 실제 SDK/Room과 연결하는 변경은 포함하지 않습니다. 두 앱의 대응 관계는 [팀 저장소 배치 안내](docs/TEAM-INTEGRATION.md)에 정리했습니다.

차량 센서 기반 자동 차계부의 로컬 IVI 시연 앱입니다. 트루 블랙, 차분한 블루, 큰 주행 수치와 상시 데모 도크로 구성했습니다.

## 실행

- **설치 없이 실행:** `index.standalone.html`을 Chrome 또는 Edge에서 엽니다. CSS, 아이콘, 경로 그래픽, 코어 로직을 한 파일에 포함했습니다.
- **개발:** `npm run dev` 실행 후 `http://localhost:3000`에 접속합니다. 소스 변경 후 브라우저를 새로고침합니다.
- **검사:** `npm test`
- **단독 파일 갱신:** `npm run build` → `index.standalone.html`, `dist/index.html`

Node.js 22에서 검증했습니다. 패키지 설치, 외부 폰트, CDN, API 키, 네트워크 자산이 필요하지 않습니다. `index.html`은 ES 모듈 진입점이므로 로컬 서버로 열고, 더블클릭 실행에는 `index.standalone.html`을 사용합니다.

## 네 화면

1. **시작:** 서비스 소개와 MOCK DATA 안내. 모의 주행 시연 시작을 누르면 11개 이벤트가 처리되고 주행 화면으로 이동합니다.
2. **주행 기록:** 12.0km, 실제 운행 35분, 두 구간, 정차 10분의 분리 표시. 단계 실행 중에는 완료된 구간만 집계합니다. 경로는 GPS 데이터가 없는 Fixture의 집 → 주유소 → 회사 개념도입니다.
3. **주유 기록:** 연료 30% → 75%, +45%p, OBSERVED. 주유량과 금액의 `null / UNKNOWN`을 미확인으로 표시합니다. 금액 입력 후에도 사건 상태 `DETECTED_UNCONFIRMED`와 주유량은 유지됩니다.
4. **조회·정정:** 5만·6.5만·7만 프리셋, 숫자 키패드, 직접 입력, UserCorrection 이력. 주유 화면에서 정정 진입 → 프리셋 → 적용의 세 번 터치로 완료합니다. 기본 65,000원은 진입 → 적용 두 번이면 됩니다.

시동 ON이면 입력 필드·프리셋·키패드·적용 버튼을 모두 잠급니다. 현재 Mock에는 속도와 기어 신호가 없으므로 **시동 OFF만 입력 허용 조건으로 사용하는 데모 정책**입니다. 실제 주행 여부를 판별하거나 차량 UX 인증을 받은 구현은 아닙니다.

## 데이터와 초기화

- 하단의 다음 이벤트 / 전체 실행 / 초기화는 모든 화면에서 접근할 수 있습니다.
- 초기화는 이벤트·여정·주유 사건·정정 이력·입력값·모의 시각·진행 상태를 처음 상태로 되돌립니다.
- 양의 정수 1~9,999,999원만 적용합니다. 숫자 뒤 문자, 소수, 음수, 지수 표기는 거부하고, 같은 금액의 중복 적용은 이력을 추가하지 않습니다.
- 노션 F03·F04와 팀 B04 파일을 대조해 중복·공백·EV 계산을 보완했습니다. JS/TS 엔진 진입점은 같은 계산 구현을 사용하며, 기존 `tests/verify-f03.js`는 그대로 유지합니다.
- 기본 UI 입력은 팀 B04 F01을 고정된 커밋에서 받은 파일로 생성합니다. `tests/fixtures/team-b04/source.json`에 출처와 파일 해시가 있고, 앱에는 기대 출력(`expected`)을 넣지 않습니다.
- 정정 시각은 실제 입력 시각을 한국 시간으로 표시하고, 센서/경로 시각은 Fixture의 11월 15일 모의 시각으로 표시합니다.
- 시연 데이터는 메모리에만 보관됩니다. 새로고침하거나 초기화하면 사라집니다.

## 검증

- 기존 F03 계약 검사 5단계와 F02 통합 검사 통과. 팀 B04 6종의 전체 출력 및 임계값/동일 시각 순서 조합 504개 검사도 통과합니다.
- 브라우저: 네 화면 전환, 단계 실행, 일괄 실행, 초기화와 재시연, 시동 ON 입력 잠금과 OFF 해제, 프리셋·키패드, 65,000원 정정 및 누적 이력, 잘못된 입력 차단 확인.
- 1280×720 (16:9), 1680×720 (21:9), 390×844 레이아웃 확인. 와이드 화면에서는 거리·시간을 세로로 배치해 경로 영역을 확보합니다.
- 초기 UI 작업에서는 코어를 유지했고, 이후 팀 데이터 대조에서 드러난 계산 문제를 보완했습니다. EV는 계산 검사 범위이며 현재 네 화면은 ICE F01 시연입니다. Mock 임계값·공백 규칙은 차량 검증 결과가 아닙니다.
- 단독 번들도 HTTP에서 검증했습니다. 자동화 브라우저의 허용 프로토콜이 HTTP/HTTPS로 제한되어 **file:// 직접 실행은 자동 검증하지 못했습니다.** 번들 내 스크립트 구문 검사와 외부 런타임 자산 참조가 없음을 확인했습니다.

F03·F04의 역할/연동 범위와 보완 근거는 `docs/F03-F04-REVIEW.md`, 시연 순서는 `F04-DEMO-GUIDE.md`, 검사 결과와 화면 캡처는 `artifacts/`를 참고합니다. 최종 영상, 원격 소스 공유 링크, Android APK는 별도 산출물이며 현재 웹 번들에 포함되지 않습니다.
